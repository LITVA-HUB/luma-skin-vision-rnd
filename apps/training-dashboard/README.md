# Luma — монитор обучения

Локальный дашборд на русском: http://127.0.0.1:8766

Запуск: двойной щелчок по `start-dashboard.cmd` либо `powershell -File ./start.ps1` из этой папки. Повторный запуск использует уже работающий монитор. Python-процесс запускается скрыто. Дашборд доступен только на этом компьютере.

Обзор показывает отдельные серии HR, P3, Seg2 и Seg1, а также все 84 пакета серии AS (63 внутренних + 21 финальный), прогноз времени, измеренную скорость, GPU, память, температуру и мощность. Графики AS используют сохранённые потери шести моделей; вкладка «Скорость» показывает шаги в секунду между измерениями. Таблица AS поддерживает фильтр, поиск, подробности и CSV. «Модели» показывает внутренние сравнения AS с обозначением их ограничений; «Журнал» — фактическое сохранение пакетов AS.

Seg2 показан после P3: дообучение сегментации на LaPa и очищенном CelebAMask-HQ. Карточка читает `D:/Luma-RnD/skin_face_transfer_v1`: регистрация, CPU/GPU-проверки, текущее состояние процесса, результаты шести траекторий и итоговое подтверждение. Доступно 40 026 обучающих снимков; 24 112 из них — дополнительные CelebA. Очередь фильтруется по составу данных и seed; фильтры и выбранный график сохраняются при обновлении API. График показывает отдельный валидационный IoU двух источников.

В Seg2 35 856 обновлений весов, шесть траекторий по 5 976 шагов. Бюджеты 1 494 / 2 988 / 5 976 сравниваются внутри каждой траектории. Завершёнными считаются только запуски с согласованными результатами и историей; счётчик прогресса не заменяет сохранение. Скорость изображений/с и прогноз выводятся из свежего реального прогресса совпадающего PID и включают загрузку/валидацию, но не итоговый аудит. При ожидании, остановке, неизвестном процессе или повреждённых данных прогноз скрыт. CPU preflight не используется для прогноза скорости GPU. Итоговый тестовый IoU появляется только с согласованным подтверждением проверки; это качество маски, а не процент фотографий с верным физическим оттенком кожи.

Карточка P3 показывает подготовку переноса «палитра → кожа», проверку GPU, обучение и итоговую проверку. В раскрываемой очереди — 72 новых пакета с фильтрами по выборке и архитектуре. 36 контрольных пакетов обычного старта будут взяты из AS/HR и не прибавляются к счётчику нового обучения. На узком экране таблица прокручивается. CPU-проверка переноса не означает улучшение точности на реальных фото.

P3 читает `D:/Luma-RnD/chromaseed_palette_transfer_v1` и подтверждение предыдущей HR из `docs/benchmarks/chromaseed_head_range_v1`. До окончания и проверки HR отображается ожидание. Шаги P3 берутся из свежей телеметрии соответствующего PID, без экстраполяции. Сохранённым считается только пакет с receipt.json, совпадающим с версией и планом. При остановке процесса, устаревших или повреждённых данных скорость и прогноз скрываются. Прогноз использует время реальных пакетов P3; начальная оценка по AS/HR помечается как предварительная. Синтетические CPU-замеры для прогноза не используются.

Текущие шаги AS отмечены ≈: исходный тренировочный процесс сохраняет подробную трассу только после пакета. Монитор не перезапускает обучение и не меняет его исходники. Фактический прогресс никогда не считается завершённым без receipt.json. ETA зависит от архитектуры и будущих выбранных шагов и не включает независимый аудит после обучения. Потери на минипакете не равны цветовой ошибке ΔE00. При разрыве связи остаются последние данные с явным предупреждением.

Источники только для чтения: `experiments/runs/chromaseed_architecture_scale_v1/*.json`, внутренние/финальные receipt.json, сохранённые inner_reviews, verification.json и датчики nvidia-smi. Изображения, веса моделей и закрытые данные не загружаются. Сервер не импортирует torch; браузер опрашивает API раз в 3 секунды.

React 19.3 / Vite 8.3 установлены только в этой папке. Исследовательские pyproject.toml, uv.lock, среда Python и замороженные исходники AS не изменяются. `npm run build` пересобирает интерфейс. `python -m pytest -q` из этой папки проверяет учёт пакетов, достоверность статуса и прогнозы.
