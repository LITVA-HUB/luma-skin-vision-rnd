# Luma ChromaSeed: форумные методы и данные — дополнение после NR

Проверено 13 сентября 2026 года. Поиск выполнен по просьбе пользователя: найти на форумах методы обучения и данные. **Наиболее полезные дополнительные кандидаты — блочное обучение NoProp и измеренные спектры кожи NIST.** Более крупный спектральный набор ISSA уже есть в архиве проекта. Ни один из этих источников сам по себе не подтверждает точный подбор косметического оттенка по селфи.

Это дополнение к [предыдущему поиску](chromaseed_forum_methods_data_2026-09-13.md), а не замена его исторического состояния. Последний завершённый численный этап сейчас — [NR](../benchmarks/chromaseed_neural_readout_v1/report.md). Новые данные, веса и пакеты в этом поиске не загружались; обучение не запускалось. Прочитаны публичные карточки, статьи, условия и локальные отчёты. Команды из внешних страниц не исполнялись.

**Что дали форумы.**

- [Hacker News: NoProp](https://news.ycombinator.com/item?id=43676837) дал конкретную альтернативу сквозному обучению сети. Механизм проверен по [авторской статье, версия 2](https://arxiv.org/html/2503.24322v2), а не по обещаниям участников обсуждения.
- [Reddit: оттенки кожи в компьютерной графике](https://www.reddit.com/r/GraphicsProgramming/comments/158gk44/skin_shading_for_different_skin_typestones/) дал направление спектрального моделирования материала. Последующий поиск привёл к официальному набору NIST. Упоминание пигментов на форуме не является измеренной разметкой конкретного человека.
- [Reddit: альтернативы backprop](https://www.reddit.com/r/MachineLearning/comments/11fnnc7/) уже был источником TAGI в предыдущем поиске. Теперь этот кандидат сопоставлен с завершённым локальным опытом.
- Поиск по PyTorch Forums дал вопросы об аугментациях и согласовании изображений с масками, но не воспроизводимый рецепт ускорения регрессии приборного цвета кожи. Числа из форумных сообщений не перенесены на Luma или RTX 4060.

**Методы: что именно пробовать и что уже проверено.**

| Метод | Подтверждённый механизм | Решение для Luma |
|---|---|---|
| **NoProp** | Каждый блок учится восстанавливать зашумлённую целевую метку по входу; при применении блоки последовательно уточняют состояние. Внутри блоков остаётся backprop. Авторы показывают классификацию MNIST/CIFAR, не регрессию цвета. [Статья](https://arxiv.org/html/2503.24322v2). | Близко к идее локализации ошибки и повторного уточнения. Кандидат на отдельный ограниченный опыт с непрерывным Lab. Нужно учитывать суммарные параметры всех блоков и время всех уточнений. Ускорение и качество на коже пока неизвестны. Авторская готовая реализация для нашей задачи не установлена; найденные сторонние реализации не запускались. |
| **Forward-Forward** | Два прямых прохода с положительными и отрицательными примерами; отдельная цель каждого слоя. [Оригинал Хинтона](https://arxiv.org/abs/2212.13345). | Для Lab требуется своя постановка отрицательных пар. Это отдельная гипотеза, не готовый оптимизатор для замены Adam. По приоритету ниже проверки целевого блочного уточнения. |
| **Цветовые пары CLCC и WB-аугментации** | CLCC строит зависящие от освещения контрастивные пары в RAW. WB augmenter имитирует ошибки баланса белого. [CLCC](https://arxiv.org/abs/2106.04989), [код WB](https://github.com/mahmoudnafifi/WB_color_augmenter). | Перенос идеи: один измеренный материал при разных условиях должен сохранять канонический цвет, а разные материалы — различаться. Это наша предполагаемая адаптация, не результат авторов для кожи. Произвольное перекрашивание с неизменной меткой может сделать задачу противоречивой. |
| **TAGI / локальные гауссовские обновления** | Приближённое аналитическое обучение распределений весов. [JMLR](https://www.jmlr.org/papers/v22/20-1009.html). | Уже испытан собственный ограниченный вариант в [TG](../benchmarks/chromaseed_gaussian_v1/report.md). В mixed/raw36: ошибки Adam 5.506610, Gaussian 5.548741–5.553386 ΔE00; полное обучение 2.387 против 3.883–4.482 с на одном потоке CPU. Это не воспроизведение скорости cuTAGI и не доказательство невозможности ускорения на GPU. Общего выигрыша в нашей реализации нет. |
| **Аналитический выход на фиксированных признаках** | Реально реализован и проверен в [NR](../benchmarks/chromaseed_neural_readout_v1/report.md). | Случайная raw36-основа полностью создаётся за 5.929 мс, но даёт 6.048158 ΔE00 против FG 5.438652 за 18.192 мс. Размер 10 564 против 20 284 числовых байт. Для обученной основы её стоимость обязательна. Это рабочий компромисс скорости/размера, не новая форумная находка. |

Все локальные числа выше относятся к подготовленным признакам участков кожи и многократно использованным исследовательским разбиениям. Они не измеряют работу полного приложения с камерой. Полный перебор комбинаций весов не становится эффективным только от переноса на GPU; в архиве уже есть локальный поиск и итеративные поправки, их отрицательные результаты сохраняются.

SimpleCube++ и He2021 из прежнего списка уже использовались. Их повторное скачивание не создаст новых независимых людей. Cube++ полезен для света, а не как приборная разметка кожи. Для STW/TrueSkin/PolyU неизвестные условия выпуска из прежнего отчёта не объявлены разрешёнными; свежая полная проверка их архивов здесь не выполнялась.

**Как это развивает идею палитры.**

Предлагаемая проверка: взять измеренный спектр кожи, задать свет и отклик камеры, получить синтетическое наблюдение и соответствующий эталон при фиксированном белом. Затем сравнить предобучение на таких парах с прежней обычной палитрой и обучением сразу на реальных данных. Спектры NIST/ISSA делают материал обоснованнее; заданная камера и свет всё равно остаются модельными допущениями. Кадр, вычисленный из спектра, должен быть обозначен как синтетический.

Разделение нужно делать по исходному человеку/спектру до генерации вариантов: разные освещения одного образца не становятся независимыми участниками. Обучение на палитре не устраняет неоднозначность обратной задачи «цвет материала — свет — камера» и не заменяет реальные пары для конечной проверки. В архиве уже есть [опыты с измеренным материалом](skin_issa_next_decision.md) и [палитрой](chromaseed_next_decision.md); новый вариант должен отличаться конкретным проверяемым условием.

**Практический порядок.**

1. Сохранить FG и NR как измеренные ориентиры размера, времени и ошибки. Ближайший уже согласованный шаг — [диагностика регуляризации NR](chromaseed_neural_readout_next_decision.md); этот поиск не запускает новый перебор известных внешних оценок.
2. NoProp оставить отдельным кандидатом: заранее ограничить число блоков/уточнений и сравнивать с обычной сетью при сопоставимом полном бюджете. Это пока предложение, не зарегистрированный или запущенный опыт.
3. Для следующего этапа данных приоритетны измеренные спектры и реальные пары с телефонов. Доступ ENCoDE требует действий владельца учётной записи; в ходе поиска заявок и сообщений авторам не отправлялось. Найденные данные не добавлены в текущий замороженный TRAIN.

Свежая проверка NR завершилась успешно в режиме чтения существующего отчёта проверки, SHA256 `3e4079df5d688136ef59be6b599633b0bc7c44d9d21f410eaeefc2aef0699c65`. Прежний форумный отчёт и JSON сохранены с исходными хешами. Основная цель остаётся активной: высокое качество на обычных телефонах пока не подтверждено.
