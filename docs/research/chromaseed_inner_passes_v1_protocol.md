# AS INNER: вклад отдельных уточнений

14 сентября 2026. Диагностика завершённых моделей AS, выполняемая во время финального обучения HR. Она не меняет очередь HR → проверка HR → P3 → Seg2 и не создаёт новое обучение.

Использовать все четыре рекуррентных архитектуры AS (soft_small, dynamic_small, soft5m, dynamic5m), три роли и три seed. Для каждой архитектуры/роли взять ровно checkpoint и learning rate из уже зафиксированного внутреннего выбора AS для четвёртого прохода. Не выбирать заново веса по внешним результатам. Всего 36 внутренних пакетов и 108 выбранных моделей из них.

Только исходный cache train.npz с хешем d7e7b4b4fc4574d620cbac8364dd8bb91be51769f4045bb8b4ddf2ad840556e0: 966 измерений, 24 исходных person codes. Для каждой роли использовать только её outer-fit часть; внутри каждого из трёх folds выводить только query-строки, не использованные этой моделью при обучении. Восстановить роли/folds по замороженным функциям и точно сопоставить rows.npz; fit/query должны разбивать разрешённую часть и не пересекаться по людям. Внешняя часть каждой роли, прежние validation/calibration/test, изображения/предсказания из evaluated и live HR exports не используются.

Основная новая информация: ошибка CIEDE2000 после проходов 1, 2, 3 и 4 при тех же весах. Главная агрегация — равный вес каждого человека и каждого seed. Дополнительно средняя ошибка по строкам и средний по seed p90. Показать все 12 сочетаний роли/архитектуры и все четыре прохода, включая ухудшения. Минимум по проходам — описательный минимум на данных разработки, не новая независимая оценка или принятая политика.

Дополнительная диагностика: в проходах 2 и 3 фиксированные пороги изменения соседних предсказаний Lab L2 [0.1,0.25,0.5,1.0,2.0]. Среди удовлетворяющих порогу строк посчитать ошибку текущего ответа, изменение ошибки к четвёртому проходу и долю случаев её увеличения/уменьшения более чем на 0.1 DeltaE00. Это описательный порог сравнения, не допуск для подбора косметики. Малое изменение ответа не является уверенностью модели. Пороги не подбираются, политика выхода не экспортируется и не принимается.

Новые native Lab traces вычисляет ранее проверенный StreamingPredictor, все строки/seed/проходы сравниваются с независимым frozen NumPy Predictor (atol1e-8,rtol0; batch-one vs batched floating-point arithmetic). Четвёртый проход дополнительно сравнивается с исходным сохранённым CUDA OOF (atol0.002,rtol1e-6). Контрольный person mean четвёртого прохода должен совпасть с AS selection clean в пределах2e-5.

Перед вычислениями зафиксировать SHA исходных файлов, cache, выбранных AS-весов/OOF/rows/receipts, AS seal/selection и предыдущего streaming qualification. CPU один BLAS-поток, CUDA context не создаётся, время ответа модели не измеряется. Сохранить все численные traces, агрегаты и исходные привязки отдельно в D:/Luma-RnD/chromaseed_inner_passes_v1. Проверка отдельно повторяет арифметику агрегатов и соответствие исходным OOF; основной запуск проверяет каждую новую trace независимым consumer. Это не повторное обучение.

Ограничение: checkpoint и LR уже отбирались по тем же INNER данным, поэтому эти оценки оптимистичны для выбора, не являются свежей валидацией политики и не доказывают улучшения на новых лицах. Используется только unit head AS; выводы нельзя автоматически переносить на wide/linear HR или палитровую инициализацию P3. После регистрации новые script/test/protocol неизменны; отчёт и запись о состоянии дополняются отдельно.
