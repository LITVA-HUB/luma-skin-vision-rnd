# Выполнение рекуррентной модели по проходам

14 сентября 2026, 11:54 МСК. Реализован и проверен отдельный NumPy/SciPy consumer для ChromaSeed AS/HR: ответ доступен после каждого реально выполненного прохода. Если остановиться после второго, третий и четвёртый не вычисляются. Обучение, веса и зарегистрированные реализации AS/HR/P3/Seg2 не изменены.

Это готовая возможность управления вычислениями. Полезное для качества правило остановки пока не выбрано. По умолчанию модель выполняет все четыре прохода; старые пороги R не переносятся. Реализация относится к soft_small, dynamic_small, soft5m и dynamic5m. Нерекуррентные patch/pool модели, в том числе текущие лидеры части задач, она не ускоряет.

## Реально пропущенные линейные операции

Число MAC на одну область кожи; одна MAC — умножение с накоплением. Счётчик учитывает линейные слои рекуррентной ветви. Значения совпали с ранее полученным независимым структурным разбором PyTorch forward.

| 2 | 144 912 | 19 943 424 | 30,34% |
| 3 | 154 488 | 24 287 552 | 15,17% |

Здесь исключены исходный предиктор-опора, нормализация, активации, арифметика attention, сортировка, перенос памяти, декодирование фото и выделение кожи. Это не проценты ускорения приложения. CPU latency пока не измерялась, GPU использовался только текущим обучением HR. NumPy consumer сохраняет FP32-нормализацию и FP64-вычисления прежней реализации; экономия памяти или размера весов не заявляется.

## Использование

Новый код: `scripts/chromaseed_recurrent_stream.py`. Он принимает ровно одну область: 36 цветовых признаков и 64×18 признаков патчей. Это внутренний интерфейс исследования; обработка фотографии в него не входит.

```python
from chromaseed_recurrent_stream import StreamingPredictor

consumer = StreamingPredictor(exported_model)
full_answer = consumer.predict(color36, patches64x18)  # четыре прохода
prefix = consumer.predict_trace(color36, patches64x18, max_passes=2)
answer_after_two = prefix.prediction

stream = consumer.iter_passes(color36, patches64x18)
try:
    first = next(stream)
    second = next(stream)
finally:
    stream.close()  # оставшиеся проходы не выполняются
```

Опциональный `exit_threshold` положительного значения сравнивает евклидово расстояние между двумя последовательными предсказаниями Lab; `min_passes` по умолчанию равен 2. Значение 0 отключает такое правило. Это не CIEDE2000, не вероятность правильности и не граница ошибки относительно прибора. В проверке использован заведомо большой порог 1e12 только для принудительного срабатывания ветки кода; он не является предложенной настройкой модели. При достижении заданного максимума причиной остановки остаётся `max_passes`.
