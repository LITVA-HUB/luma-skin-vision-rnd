# Проверка похожих копий LaPa / CelebAMask-HQ

14 сентября 2026. Узкая проверка качества данных перед Seg2: сравнить содержимое фотографий между источниками на разрешённых TRAIN/VALIDATION рядах. Не использовать лицо как идентификатор, биометрические признаки, авторские person codes, маски, целевые цвета или результаты нейросетей. TEST-фотографии и пользовательские пять фото не включаются. Проверка не меняет уже зафиксированные данные/регистрации.

Покрытие: LaPa TRAIN15914/VAL1692 и CelebAMask-HQ TRAIN24112/VAL2992, всего44710 строк. Проверить хеши массивов/индексов против Seg2 registration c92d12e53e42325cec76fd6ad61dc94a8c685fcba9a48b97ccc0a791d108da88. Читать только выбранные глобальные индексы CelebA; полный массив содержит также невыбранные строки. Контроль целостности файла хеширует байты полного массива, но TEST-строки не преобразуются в признаки и не оцениваются.

Метод: RGB уменьшается Pillow LANCZOS до64x64; grayscale до32x32, DCT-II ortho, верхний8x8 блок, DC исключён,63коэффициента сравниваются с их медианой. 64-битный код с нулевым первым битом служит поисковым отпечатком. Сравнить каждый LaPa с каждым выбранным CelebA и его горизонтальным отражением, полным перебором Hamming<=8 в блоках. Изображения с gray std<8 пометить малоконтрастными и пропустить в этом поиске; показать их число.

Для всех кандидатов вычислить корреляцию grayscale64x64 и среднюю абсолютную разницу RGB64x64 в единицах0..255. Сильные кандидаты: корреляция>=0.995 и RGB MAE<=8. Сохранить все кандидаты, не только сильные. Сильные пары нужно просмотреть как содержимое изображения перед выводом о копии. Не объединять людей и не исключать строки автоматически по одному hash/correlation.

Ограничения: полнота обнаружения не установлена. Кропы, повороты, сильные правки, альтернативные кадры и совпадение людей без совпадения изображения не покрыты; внутри каждого источника новый поиск не выполняется; TEST не покрыт. Отсутствие кандидатов не доказывает независимость людей или отсутствие всех утечек. Высокая корреляция — сигнал для проверки, не доказательство одной фотографии.

Новые script/test/protocol и используемые входы связать хешами перед основным поиском. Вычисления CPU, без Torch/CUDA или замера задержки ML. Результаты/миниатюры остаются локально в D:/Luma-RnD/data_growth_2026_09_14/cross_source_similarity_v1. После фактического окончания HR запустить его зафиксированный полный аудит; новые ML-задания по-прежнему только после предусмотренных проверок.

Реализация опирается на первичные API: [SciPy dctn](https://docs.scipy.org/doc/scipy/reference/generated/scipy.fft.dctn.html), [NumPy bitwise_count](https://numpy.org/doc/stable/reference/generated/numpy.bitwise_count.html). Пороговые правила — локальные правила скрининга, не опубликованный стандарт определения дубликатов.
