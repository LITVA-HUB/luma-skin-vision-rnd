# Воспроизводимость и проверка публикации

[Архив](README.md) · [Состояние остановки](STOP_STATUS.md) · [Предыдущая инструкция](../../publication/REPRODUCIBILITY.md)

## Проверить этот архив, не запуская исследование

Нужен Python 3.11+ для проверки. Проверяющая программа использует стандартную библиотеку, не импортирует Torch/модели, не читает наборы фотографий, не запускает CUDA, обучение или inference.

```bash
python scripts/verify_complete_archive.py
```

Проверяется покрытие всех benchmark-папок и Python-модулей, точное соответствие перенесённых файлов и reports хэшам, все исходные таблицы, тестовые определения, локальные ссылки новой документации, наличие ключевых отрицательных/неполных результатов. Тесты архитектур инвентаризируются, а не выдаются за заново пройденные. Итог: [validation.json](validation.json).

Для пересборки статического справочника:

```bash
python scripts/build_complete_archive.py
python scripts/build_archive_figures.py
python scripts/verify_complete_archive.py
```

Вторая команда требует Matplotlib/NumPy и строит только графики из сохранённых JSON. Первая читает Python как текст через AST и не выполняет исследовательские модули. Не запускайте старый `build_research_archive.py` поверх новой публикации: он исторически генерировал текст и историю предыдущего этапа. Его исходник сохранён для воспроизведения старого оформления.

## Воспроизвести научный опыт после отдельного возобновления

Каждая [карточка серии](EXPERIMENTS.md) ведёт к своему протоколу, model card, `reproduce.md` при наличии, скриптам обучения/аудита и JSON зависимостей. Полные `pyproject.toml` и `uv.lock` соответствуют исследовательскому снимку. Программы рассчитывают на зарегистрированные данные, parent checkpoints, версии библиотек и локальную структуру каталогов. Это не полностью переносимый one-command запуск на произвольной машине.

На последнем этапе использовались Windows, RTX 4060 8 ГБ и PyTorch 2.8.0+cu128. Конкретные версии, device, seed, число BLAS threads, режим eager/CUDA Graph и guards следует брать из протокола нужной серии. Одно и то же имя функции не гарантирует побитное совпадение на другом BLAS/GPU/driver. Допуск сравнения должен оставаться исходным.

Порядок воспроизведения: получить исходные данные согласно документации источника → проверить их хэши и split → восстановить точные parent artifacts → проверить регистрацию → выполнить полный fit и frozen INNER-выбор → получить результаты → отдельно выполнить предусмотренные audit/runtime → собрать итоговый отчёт. Старые TEST и повторно используемые роли остаются раскрытыми. Новое выполнение не превращает их в свежую независимую проверку.

Исторические скрипты содержат абсолютные локальные пути. Для запуска на другой машине нужна явная адаптация путей в новой регистрации; нельзя менять оригинальную source lock и выдавать изменённый опыт за тот же. Данные и большие веса отсутствуют в Git; подробности в [реестре артефактов](MODEL_ARTIFACTS.md).

## Что именно проверялось исторически

Тесты охватывают формы/конечность входов, семантику выборки и групп, подбор только на INNER, соответствие NumPy/PyTorch, payload export, guards, ролевые ограничения и сохранение состояния. В каталог включено полное тело каждого теста и его decorators; это позволяет проверить, что именно утверждает код. Некоторые тесты параметризованы, другие требуют данных или специальных условий.

Ранее опубликованные 379 passed относятся к полному запуску этапа 11 сентября. Позже добавлялись scoped-наборы: например, 34 проверки host-recovery, 32 проверки подготовки Seg2 и другие зафиксированные receipt. Они не суммируются в «текущие все тесты прошли»: наборы пересекаются и запускались в разное время. Для текущей публикации отдельно выполняется только проверка архива.

## Сохранность исходных доказательств

Исходные frozen files скопированы побайтно. Публикационные индексы, рассказы, схемы и графики — производные документы. `import_manifest.json` связывает каждый новый импорт с исходным SHA-256 и scope; `figure_provenance.json` связывает графики с JSON. Локальные фотографии, матрицы данных и Windows desktop telemetry в публикацию не входят. Отсутствие файлов объяснено, а не замаскировано под успешную проверку.

Дополнительно проверены SHA-256 содержимого самих Git blobs: [git_snapshot_validation.json](git_snapshot_validation.json). Это обнаруживает нормализацию концов строк при добавлении в Git, которую одна проверка рабочего каталога могла бы пропустить. Форматирование замороженных свидетельств сохранено; lint и whitespace проверяются у новой публикационной реализации.
