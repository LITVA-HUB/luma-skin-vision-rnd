# IMPORTANT SCIENTIFIC CORRECTION

Do NOT formulate the task as:

“Recover the true physical skin color from any JPEG under arbitrary unknown illumination and arbitrary unknown camera.”

That statement is physically too strong.

A processed smartphone image depends on multiple unknown factors:

* spectral illumination;
* camera spectral sensitivity;
* automatic white balance;
* exposure;
* tone mapping;
* local ISP processing;
* geometry;
* specular reflection;
* shadows;
* cosmetics;
* compression;
* potentially HDR/multi-frame processing.

Different physical situations can result in similar pixels.

Therefore the scientifically defensible task is:

> Estimate a predefined colorimetric target for specified facial skin regions within a documented operating domain, and estimate whether an input lies in a regime where the target can be estimated reliably.

The system must be allowed to abstain.

# HYPOTHESIZED TECHNOLOGICAL CONTRIBUTION

Do NOT assume this is novel.

Treat it as a research hypothesis requiring prior-art and experimental validation.

Investigate whether the following specific combination can produce a measurable technical advantage:

## 1. Measurement-aware skin ROI reliability

Do not train a model only to answer:

“Is this pixel skin?”

Instead investigate a model that estimates:

“How suitable is this skin region for measuring the defined colorimetric target?”

Potential unreliable regions include:

* highlights;
* deep shadows;
* clipped areas;
* facial hair;
* eyebrows;
* lips;
* eyes;
* hair;
* makeup where prohibited by protocol;
* occlusions;
* strongly non-uniform illumination;
* unfavorable local geometry.

A region can be anatomically skin and still be poor for color measurement.

This distinction is important.

Investigate training ROI reliability against measurement error where possible.

---

## 2. Bounded photometric hypotheses

Do not blindly apply a single white-balance correction.

Preserve the original color signal.

Investigate a small bounded family of physically/plausibly motivated photometric transformations.

Potential examples:

* no correction;
* Gray World;
* Shades of Gray;
* constrained channel gains;
* global color correction;
* device-conditioned correction when metadata exists;
* regional correction where justified.

Do NOT use generative beautification or arbitrary image enhancement as measurement correction.

For the same facial regions, compute how the estimated target changes across plausible photometric explanations.

---

## 3. Photometric ambiguity representation

Define features describing instability such as:

* disagreement between correction hypotheses;
* disagreement between facial regions;
* sensitivity to small ROI perturbations;
* local illumination gradients;
* clipping;
* highlight indicators;
* shadow indicators;
* out-of-distribution features;
* camera/domain features when available.

Investigate whether these features predict real ΔE00 error better than:

* detector confidence;
* softmax confidence;
* regression magnitude;
* generic image-quality scores.

---

## 4. Error / reliability prediction

Build a dedicated error model.

Potential targets:

* predicted ΔE00;
* probability that ΔE00 <= predefined tolerance;
* rank of expected measurement error;
* calibrated prediction interval.

Train this component using held-out/out-of-fold residuals.

Do NOT train the error head on optimistically fitted training residuals and call it calibrated uncertainty.

---

## 5. Selective prediction / abstention

Define:

ACCEPT
RETAKE
UNSUPPORTED

The system must be evaluated using risk-versus-coverage analysis.

The key question is:

At the SAME coverage, is the proposed method more accurate than the best baseline?

Not:

“Does accuracy improve if we reject almost everything?”

# GO / NO-GO GATES

Implement explicit research gates.

## GATE 1 — MEASUREMENT VALIDITY

Question:

Can the chosen ground-truth protocol itself measure the target with acceptable repeatability?

If NO:

fix the measurement protocol before training.

## GATE 2 — PROBLEM EXISTS

Question:

Does the same subject actually show material cross-device / cross-lighting error under naïve baselines?

If NO:

do not build an unnecessary complicated model.

## GATE 3 — ML VALUE

Question:

Does standard compact ML materially improve over classical methods?

If NO:

a classical/hybrid technology may be more appropriate.

## GATE 4 — PROPOSED INNOVATION

Question:

Does the proposed ambiguity/reliability method improve over strong matched baseline C+?

If NO:

do not claim the mechanism as successful innovation.

Analyze why and pivot.

## GATE 5 — SELECTIVE VALUE

Question:

At a commercially useful coverage level, does abstention materially reduce unacceptable measurement error?

If NO:

the confidence system may not provide enough product value.

## GATE 6 — DEPLOYMENT

Question:

Can the result be transferred into a compact model without destroying the advantage?

If NO:

measure the accuracy/compute tradeoff and choose honestly.
